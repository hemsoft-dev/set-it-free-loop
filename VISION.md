## Executive Summary

Software engineering is shifting from one-off automation to **self-improving systems**.

The Set it Free Loop is a **continuous engineering quality system** that:

- Detects problems and feature requests continuously
- Converts findings into trackable GitHub Issues (one canonical queue)
- Generates and validates fixes via AI-assisted PRs
- Gates quality with deterministic checks (lint, typecheck, tests, security)
- Re-runs analysis until confidence is high
- Ships, closes the loop, and learns

This is not "AI writes code." It is **AI + deterministic gates + governance + feedback loops** operating as a continuous quality system at repository scale, then organization scale.

See [SOLVING-SOFTWARE-ENGINEERING.md](SOLVING-SOFTWARE-ENGINEERING.md) for the full operational playbook.

## Core Loop

```
1. Observe      — Scheduled repo-audit scans repository state
2. Convert      — Audit emits one or more actionable GitHub Issues
3. Fix          — Fixer workflow claims eligible issues, opens PRs
4. Verify       — CI quality gates run (lint, typecheck, tests, coverage, security)
5. Review       — PR-analysis workflow checks risk/severity, blocks weak PRs
6. Resolve      — Merge when thresholds pass; close linked issue(s)
7. Learn        — Record outcomes, tune prompts/rules/thresholds
```

The system is recursive but **bounded** by explicit governance controls.

## Strategic Goals

1. **Reusable Workflow Library** — A versioned catalog of `gh aw`-compatible workflows deployable to any repo
2. **Governed Automation** — Label taxonomy, retry policy, merge authority matrix as code in `deployment/governance/`
3. **Staging Gate** — Nothing enters the production library without running on this repo first
4. **Structured Intake** — `CATALOG.md` for what's ready, GitHub Issues for
   proposed work, `TODO.md` for the active implementation backlog, and
   `/new-workflow` for authoring
5. **Fleet Deployment** — A single PowerShell script deploys any workflow to N repos via PRs
6. **Consumer Independence** — Consumer repos reference workflow files by SHA pin; upgrades are explicit
7. **Operating Model, Not a CLI** — The value is the governance standard and workflow library, not a wrapper around `gh aw`

## Architecture

### Repo Structure

```
HemSoft/set-it-free-loop/
├── .github/
│   ├── workflows/          ← STAGING (dogfood on this repo)
│   └── prompts/            ← VS Code Copilot intake prompts
├── deployment/             ← everything a consumer repo needs
│   ├── workflows/          ← PRODUCTION workflow library
│   ├── governance/         ← labels, policy, setup scripts
│   └── scripts/            ← fleet deployment tooling
├── docs/                   ← maintainer reference
├── CATALOG.md              ← graduated, deployable workflows
├── TODO.md                 ← active implementation backlog
├── VISION.md               ← this file
├── SOLVING-SOFTWARE-ENGINEERING.md
└── README.md
```

### Workflow Lifecycle

```
/new-workflow prompt
    ↓
.github/workflows/{name}.md   ← STAGING
    ↓  acceptance criteria pass
deployment/workflows/{name}.md ← PRODUCTION (CATALOG entry created)
    ↓  deploy-workflow.ps1
Consumer repo .github/workflows/{name}.md ← IN USE
```

### Consumer Integration

Consumer repos reference workflows by SHA pin in the `source:` field:

```yaml
source: HemSoft/set-it-free-loop/deployment/workflows/repo-audit.md@<sha>
```

SHA pinning ensures: (1) reproducibility — runs exactly what was tested, (2) security — no silent upstream changes, (3) controlled upgrades — you choose when to move to a new SHA.

## The sfl: Metadata Standard

Workflows in this library carry a lean `sfl:` metadata block alongside the standard `gh aw` frontmatter. The `sfl:` block adds only what `gh aw` genuinely lacks — it is additive and non-breaking.

## Quality Gates

Every fix generated by the loop must pass gates in this order:

1. **Policy Gate** — allowed tools, allowed paths, write limits
2. **Syntax Gate** — formatting, markdownlint, static validation
3. **Compilation Gate** — typecheck/build must pass
4. **Test Gate** — unit/integration tests + minimum coverage
5. **Security Gate** — secret scanning, dependency review
6. **Risk Gate** — agent review severity threshold
7. **Merge Gate** — all required statuses green

## Rollout Strategy

### Phase 1 — Observe (current)

- Audit only, no code changes
- One issue per run
- Tune signal quality

### Phase 2 — Assisted Fixing

- Auto-PR for low-risk categories only
- Human review required for merge
- Measure fix success and rework rate

### Phase 3 — Guarded Autonomy

- Auto-merge for tightly bounded risk classes
- Strict hard gates and escalation controls
- Expand repo count gradually

- Mean time to remediation for audit findings
