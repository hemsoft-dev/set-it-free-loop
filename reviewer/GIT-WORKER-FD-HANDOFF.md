# Git worker descriptor handoff research

Research dated October 21, 2026. This is an offline design review, not a production factory or launch qualification. The background research used source reads and `uname -r`. The implementation subsequently ran inert kernel/namespace fixtures described in [GIT-GRANT.md](GIT-GRANT.md). No credentials, inference or policy exceptions were exercised.

## Consequences for the proposed layout

FD3 must survive both exec transitions without CLOEXEC, then become CLOEXEC in the trusted worker before spawning Git. There is no automatic payload descriptor allowlist. Close every unexpected inherited descriptor explicitly. FD9 can reference the original root-owned `/usr/bin/bwrap` and carry CLOEXEC when executing that ELF through `execveat(AT_EMPTY_PATH)`; it then disappears during the initial exec. The launcher must prove the actual descriptor table. [Exec descriptor semantics](https://man7.org/linux/man-pages/man2/execve.2.html), [execveat](https://man7.org/linux/man-pages/man2/execveat.2.html).

Inference: neither proposed memfd bind is usable as specified. A memfd exposes a synthetic deleted pathname, which cannot satisfy ordinary canonical pathname resolution. A fixed `/worker` placeholder does not repair the source. Candidate requiring qualification: retain FD5 and execute `/proc/self/fd/5` directly, preserving the sealed inode, then close FD5 in the worker. Inspect the executable from the host while the worker waits inert. Verify executable seals, mode and exact identity. [Memfd interface and example](https://man7.org/linux/man-pages/man2/memfd_create.2.html), [host executable access](https://man7.org/linux/man-pages/man5/proc_pid_exe.5.html).

Executing a retained original bwrap FD does not by itself prove the intended AppArmor transition or permission to create user namespaces. Qualify the loaded profile and resulting label on the target host. Do not copy bwrap to a memfd and assume the same policy. [Ubuntu's userns policy](https://ubuntu.com/blog/ubuntu-23-10-restricted-unprivileged-user-namespaces).

Design requirement: retain mandatory `--unshare-all --unshare-user --disable-userns`. The inherited unit may allow AF_UNIX and AF_NETLINK during bootstrap, while denying Internet families. The fixed final filter must deny non-AF_UNIX socket creation, namespace changes, mount APIs, ptrace, process_vm, pidfd_getfd and io_uring across supported ABIs. Seccomp restrictions compose and survive exec; they do not revoke inherited sockets. Descriptor auditing is therefore essential. [Seccomp interface](https://man7.org/linux/man-pages/man2/seccomp.2.html), [systemd address-family limitations](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#RestrictAddressFamilies=).

For `/dev`, prefer a broker-prepared small tmpfs with explicit `noswap,size=...,nr_inodes=...,noexec,nosuid`, fixed placeholders and only device-enabled binds for null/urandom, then remount its directory read-only. Avoid shm/devpts/run additions. This remains a proposal. Existing proc/dev/work/broker placeholders are sufficient except any new fixed file destinations must exist before the immutable root is bound. Binds retain the same filesystem, so tmpfs byte/inode accounting and noswap persist. Bubblewrap preserves existing noexec when remounting binds and adds nosuid/nodev unless device-enabled. Inspect final submount flags separately. A read-only parent does not make writable submounts read-only. [Tmpfs limits](https://docs.kernel.org/filesystems/tmpfs.html), [bind remount implementation](https://github.com/containers/bubblewrap/blob/124c4cdf4321f63ef17a1cb0ce8f9dd45bd7adbe/bind-mount.c#L439-L476), [mount semantics](https://man7.org/linux/man-pages/man2/mount.2.html).

## Protecting worker descriptors and retaining measurements

Fact: opening `/proc/parent/fd/N` uses PTRACE_MODE_READ_FSCREDS. A nondumpable worker denies this to Git with no CAP_SYS_PTRACE in the worker's user namespace. CLOEXEC alone leaves the parent's descriptors exposed. Set worker dumpability to zero before launching Git, drop all capability sets, retain NNP and the final filter. Do not exec the worker away afterward: ordinary exec resets dumpability to one. Git's own reset does not change its still-running parent's setting. [FD access](https://man7.org/linux/man-pages/man5/proc_pid_fd.5.html), [ptrace checks](https://man7.org/linux/man-pages/man2/ptrace.2.html), [exec attributes](https://man7.org/linux/man-pages/man2/execve.2.html).

Host `/proc/PID/exe`, fd and namespace dereferences use related ptrace checks and may fail after this transition. They do **not universally fail**: a same-UID supervisor in an ancestor user namespace may have CAP_SYS_PTRACE in the descendant through namespace ownership, even with host CapEff zero. LSM policy can further restrict access. [Namespace links](https://man7.org/linux/man-pages/man7/namespaces.7.html), [Linux 6.17 capability ownership walk](https://github.com/torvalds/linux/blob/v6.17/security/commoncap.c#L68-L109).

Proposed phase protocol: host authenticates and holds worker inert, measures executable/root/mounts, opens typed namespace FDs, then authorizes dumpable-zero and acknowledges that transition before any Git launch. Keep original pidfd/liveness/start identity and namespace FDs throughout. Retained FDs pin namespace identity, but cannot prove the worker still occupies it. Require immutable inherited namespace-denial policy plus phase evidence; never silently substitute reopening after zero. For each independently authenticated Git helper, open its namespace while permitted and compare device/inode/type against the retained worker namespace. If peer inspection fails, deny admission. [Namespace FD lifetime](https://man7.org/linux/man-pages/man7/namespaces.7.html), [namespace type](https://man7.org/linux/man-pages/man2/NS_GET_NSTYPE.2const.html).

## Authenticating the supervisor across PID namespaces

Linux 6.17 converts SO_PEERCRED PID through `pid_vnr`, so the outer supervisor appears as PID zero inside. SO_PEERPIDFD instead uses stored `sk_peer_pid` directly, without that translation or a visible-PID lookup. It can identify the outside peer. [Credential conversion](https://github.com/torvalds/linux/blob/v6.17/net/core/sock.c#L1691-L1703), [peer pidfd](https://github.com/torvalds/linux/blob/v6.17/net/core/sock.c#L1905-L1944).

On 64-bit Linux 6.17, pidfs assigns an identifier per `struct pid`, uses it as the inode, and shares the stashed object across opens. Compare both `st_dev` and `st_ino` with a supervisor pidfd inherited through a trusted launch path; require `fstatfs` PID_FS_MAGIC `0x50494446` and liveness. The pidfs pseudo-inode has
no S_IFMT bits, rather than S_IFREG. A later actual mini probe verified
mode0700, no file type, PID_FS_MAGIC, CLOEXEC and non-readable live polling.
An initial regular-file check incorrectly rejected that kernel producer and
was corrected before qualification. Preserve the original trusted pidfd, never reopen a numeric PID from payload input. On 32-bit 6.17, inode alone can collide; generation/file-handle comparison is required, so reject that ABI for this design. Linux 6.9 already provides pidfs, but a minimum version alone is insufficient qualification. [Identifier rules](https://github.com/torvalds/linux/blob/v6.17/fs/pidfs.c#L100-L140), [inode assignment](https://github.com/torvalds/linux/blob/v6.17/fs/pidfs.c#L867-L879), [allocation](https://github.com/torvalds/linux/blob/v6.17/fs/pidfs.c#L1013-L1064), [6.9 implementation](https://github.com/torvalds/linux/blob/v6.9/fs/pidfs.c#L125-L160), [pidfd polling](https://man7.org/linux/man-pages/man2/pidfd_open.2.html).

An inherited control socket is another design option. Socketpair SO_PEERCRED describes its creator, not the later worker holding an endpoint. With SO_PASSPIDFD, per-message SCM_PIDFD derives from the sender; require it alongside credentials, reject ancillary truncation, and compare the kernel pidfd to the trusted identity. An inherited socket endpoint alone does not authenticate which process sent a packet. [Socketpair identity](https://github.com/torvalds/linux/blob/v6.17/net/unix/af_unix.c#L1830-L1860), [SCM_PIDFD delivery](https://github.com/torvalds/linux/blob/v6.17/net/core/scm.c#L465-L551), [SO_PEERCRED timing](https://man7.org/linux/man-pages/man7/unix.7.html).
