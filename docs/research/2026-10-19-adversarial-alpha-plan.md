## Default review protocol

Default mode is `adversarial`, with both subscription adapters implemented in v1:

1. R1: Codex and Claude independently inspect one immutable head/base-tip/merge-base snapshot. They receive the same initial evidence packet and source capabilities, with no peer output. Record actual reads because equal access does not mean equal evidence inspected.
2. R2: after both R1 outputs validate, each gets both frozen R1 reports. It must address every peer finding ID with a cited confirmation, rejection, duplicate reference, or inability to verify. It may withdraw its own R1 findings. Proposed test cases are not recorded as executed tests.
3. A deterministic Go ledger renders the result. There is no third adjudicator model and no forced consensus. Four sessions provide mutual cross-examination, not a response to the peer's R2 critique. An explicit owner option permits one further paired round for disputes/late findings, at most six sessions total. Select the optional paired extra round in trusted per-PR configuration before request admission. Alpha does not offer extension after completion; changing the round setting requires a new native request. Both selected extra phases must validate for completion.

These limits count reviewer sessions, not individual inference requests. Internal turns, tools, and transport retries consume additional usage and require separate bounds. Sessions are sequential in the alpha, with one active job.

Use finding IDs and preserve provenance, objections, source references, severity disagreement, and lineage through deduplication. Final statuses are `corroborated` for explicit source-grounded peer confirmation, `disputed` for substantive unresolved objections, `unverified` for insufficient examination or new R2 allegations, `retracted` for origin withdrawal, and `invalid` for schema/source-reference failure. Independent overlapping allegations alone do not prove correctness. Even corroboration is model-assessed, not a verified defect.

New R2 findings remain unverified in a separate section until explicitly peer-examined in an optional R3. R3 receives both frozen R2 reports and finding lineage. It permits responses to objections and peer examination of late findings. A late finding may become model-assessed corroborated only after explicit source-grounded peer confirmation in R3. Preserve prior objections/dispositions; unresolved objections remain disputed. New R3 allegations stay unverified, with no further round. Selecting R3 requires both additional phases for completion. Valid paths and quotes establish location, not semantic truth; they never promote a late finding. Only corroborated findings receive ordinary inline comments by default; disputes and late findings remain visible in clearly labeled summary sections. A peer rejection never silently erases the original allegation. Failed schema/protocol output is a failed phase, not a clean review.

Both required providers/phases must complete on the same snapshot/configuration for `dual_complete`. A provider outage, quota wait, or invalid output cannot produce successful single-provider completion. Preserve successful phase artifacts for bounded same-snapshot resume. Partial outcomes have visible INCOMPLETE status and no implicit clean/pass result. Alpha publishes no substantive partial findings, only a non-substantive status and cause.

## Per-PR configuration

Trusted controller defaults select `adversarial`, one peer round, and a pinned allowlisted model for each provider. Sticky per-PR records override those defaults. Support explicit `independent-pair`, `codex-only`, and `claude-only` selections; failed dual runs never switch modes automatically. `independent-pair` runs two independent R1 sessions without cross-examination. Each single-provider mode runs one R1 session. Completion records the selected mode and its required phases; selecting these modes is not incomplete execution. Without peer examination, findings remain unverified in the summary. Four/six-session rules apply to adversarial mode.

Use one primary configuration surface: a typed PR comment command such as `/sfl config mode=adversarial`, with `show` and `reset`, plus `/sfl cancel`. Only Franz's verified immutable GitHub user ID can create an accepted command. Configuration does not request inference; GitHub's native Reviewers selection remains the trigger. A local CLI wrapper is optional and posts the same command, rather than introducing a second configuration store or control API.

Ignore non-owner commands without replies or GitHub writes and rate-limit owner acknowledgments. Record the head repository ID, including fork heads. Capture command ID, author ID, original body hash, effective configuration hash, policy version, exact provider/model/client identities, auth modes, budgets, and snapshot IDs in each job. Reject edited-before-admission commands, unknown keys/models, raw CLI arguments, endpoints, paths, and credentials. PR files/body, bot comments, and model output cannot configure the service.

After acceptance, command edits/deletions cannot rewrite the durable decision; use a fresh command to change it. A config change applies to the next request and is acknowledged as such. Running/resumable jobs keep their captured configuration. A configuration acknowledgment identifies its durable version. Requests created after that acknowledgment use that version; earlier requests retain the preceding version regardless of discovery order. Ambiguous ordering defers admission. Recovery reconstructs the same mapping from persisted records. Persist configuration acknowledgment intent, version and unique remote marker before dispatch. If its write outcome is unknown, defer dependent review admission until paginated remote reconciliation recovers the acknowledgment identity/time. Never blindly post another acknowledgment after an uncertain write. Fault tests cover a crash after GitHub accepts the acknowledgment but before local response persistence. `/sfl cancel` advances generation and blocks future publication; a new native request is needed to run replacement settings. Completed reviews do not rerun automatically on pushes or config changes.

Use a supervised private polling service and durable SQLite ledger, not Actions or public webhooks in the initial version. The sole target is immutable repository ID `1169772257`; reject all other repository IDs before provider work or writes. The trusted controller collects immutable Git objects and PR metadata. Each provider runs the pinned unmodified official CLI in a separate disposable guest/process environment with its own authentication store. The model receives no GitHub token. A separate publisher has no provider credentials and resolves destinations from the trusted job record, never model output.

Disable ambient repository hooks, settings, plugins, and MCP servers. Keep target source, including configuration files and instructions, as inert review input. No shell, arbitrary file reader, browser, Docker socket, SSH agent, host home, LAN/private-network services, or other job's state is available to the model. The only allowed source tool is a trusted reader/search service under a separate OS identity scoped to immutable job Git objects. Launch it without provider credentials, not as a child inheriting the CLI environment. Permit required provider egress and the job-local reader connection only. These properties require hostile-fixture verification; containers or client permission flags alone do not prove them. If a pinned client cannot remove a forbidden capability, record that provider's live use as blocked. Do not relax the boundary or declare v1 complete. A different isolation contract, such as a model-accessible shell confined to a snapshot guest, requires an explicit owner decision.

The first credential-bearing probes occur only inside the restricted probe environment after its configuration/network controls are checked. Claude bare mode conflicts with its subscription-token path, and permitted-without-prompt tools are distinct from available tools. Exact supported pinned-client controls must be tested, including disabled built-ins and separate strict MCP control. Codex requires its own proven tool/sandbox boundary rather than an assumption of identical CLI features. [Claude CLI](https://code.claude.com/docs/en/cli-reference), [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode).

Allowlist process environments and verify actual subscription auth before every phase. Codex refresh state has a separate protected serialized store with write-back outside disposable job state; do not share Franz's interactive login file or overwrite refreshed state with an old seed. Neither provider may inherit the other's credentials. Verify paid overflow is disabled or an enforceable worker-specific block exists. Estimated dollar caps are not billing guarantees. [Subscription usage credits](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans), [Codex credits](https://learn.chatgpt.com/docs/pricing).

Bound each phase's duration, turns, source/tool calls, input/output size, memory, retries, and retention, plus total job/session and daily review limits. Recognized quota waits have expiry/reset policy; transient errors have finite retries; unknown errors are visible failures. Capacity is measured, not inferred from subscription price. Retain structured artifacts/hashes/provenance with explicit retention; raw transcripts are not uploaded to public GitHub. Record omitted paths, missing history, truncation, binaries, submodules and reader-limit exhaustion. Unreadable or omitted material never counts as clean. Preserve source-valid findings that cannot anchor in the diff as summary findings. Render model text as untrusted content: neutralize mentions, prohibit remote images/raw HTML and allow only explicitly approved links. Generate source links from trusted snapshot/path data.

## Publication and self-review integrity

Persist request/removal/re-request identities, requester/event provenance, generations, leases, phase artifacts and publication intent/outbox in SQLite. Reconcile paginated history after downtime and defer inference when requester attribution is uncertain. Head or base-tip movement invalidates unpublished work even if merge base is unchanged. Recheck authorization, request generation and both revisions before and after publication. Never mark request B fulfilled by A's review. If A's in-flight publication removes B's native pending state, retain B unresolved locally, record ambiguity and pause for reconciliation. Never dispatch A after cancellation or replacement is known to the publisher. Failure to establish an acceptable recovery path blocks live publication. No blind retry after an uncertain POST. GitHub lacks an atomic compare-and-publish condition across those states: initial output always names its snapshot; supersession is recorded locally and annotated on GitHub when access permits. COMMENT reviews are advisory, with human merge and ordinary checks independent. [Review API](https://docs.github.com/en/rest/pulls/reviews).

Bootstrap implementation PRs use manual reviews. Later alpha reviews run a separately promoted trusted build, model/policy configuration, and reader/publisher version. A candidate PR is always inert data, including changes to prompts, auth, source tools, policy, allowlist, controller, publisher, and runtime packaging. Merging candidate code never automatically promotes it into the credential-bearing reviewer. Do not restore the retired service or broaden to other repositories.
