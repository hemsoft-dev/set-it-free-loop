# Organization App rollback and hs-buddy pilot

The central SFL App reviewer was qualified on mini using hs-buddy, then paused.
Native Codex remains the review engine. No consumer SFL workflow, model key or
App key was needed in hs-buddy. The pilot check is advisory; existing CI, CodeQL
and review thread requirements remain. Broader activation is not authorized by
this report.

[Issue #139][receipt-1] tracks delivery. [Machine-readable inventory and
receipts](2026-10-09-pilot.json) contains all 69 repository observations, 47
closed proposals with retained branch tips, removal paths, protection
preservation, publisher identities and delivery IDs.

## Hosting and review initiation

The existing SFL App is installed for all 69 organization repositories and
future repositories. The central pilot cannot widen eligibility beyond immutable
hs-buddy ID 1229335234. Its in-memory installation token has access only to that
repository with Checks write and Contents, Issues, Pull requests read. The App's
preexisting wider permission registration is unchanged.

Mini receives signed HTTPS webhooks at
`https://mini.tail3280fc.ts.net:10000/webhook`. Explicit subscriptions are
pull_request, pull_request_review, issue_comment and push; the real GitHub ping
returned HTTP 200. Existing mini port 8443 routing remains unchanged.
Credentials and persistent state use mode 0600, directories 0700, and the user
service recovers on restart. The JSON receipt records the installed source
revision and binary hash.

hs-buddy follows the enabled native Codex personal preference, On PR open. The
initial pilot review was initiated automatically and produced a real finding.
Substantive documentation fixes and the later context-recovery commit each used
one human `@codex review` request. The service neither assumes an App bot
inherits a human connection nor calls a model API. See the
[runbook](../../central-reviewer/README.md).

## Synthetic controls and limits

The source's race-enabled HTTP-backed test suite covers findings, malformed or
spoofed results, edited/deleted evidence, shared heads, head/base changes,
out-of-order delivery, durable recovery and queue/rate-limit failures. These are
synthetic GitHub API fixtures, not a claim that every negative control was
performed against production. Actual context invalidation and duplicate
redelivery are above.

GitHub association APIs omit closed-unmerged PRs. A separate paginated scan
checks those PRs' recorded final heads. It does not prove that an abandoned
intermediate historical commit never appeared in a closed PR. This remains an
explicit pilot coverage limit. Native formats outside the verified contracts
require attention. API verification errors attempt to withdraw green proof; a
GitHub write outage or rate limit can prevent immediate withdrawal and remains
visible in durable recovery. No new required SFL check or fleet activation was
installed.
